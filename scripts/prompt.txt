    class="vulnerability__body">\n            <div><h2>Executive
    summary</h2>\n<p>A vulnerability, known as "Copy Fail", has been identified
    in the Linux kernel\'s cryptographic interface. A user with a local account
    could trigger the flaw to gain root privileges, such as that of a system
    administrator.</p>\n<p>This issue has been assigned <a
    href="https://access.redhat.com/security/cve/CVE-2026-31431">CVE-2026-31431</a>
    and has a severity impact of <a
    href="https://access.redhat.com/security/updates/classification">Important</a>.
    Configuration settings can be used to further mitigate the
    impact.</p>\n<p>Even though the severity is less than Critical, Red Hat has
    expedited the release of fixes. All fixes <a
    href="https://access.redhat.com/security/cve/cve-2026-31431#cve-affected-packages">are
    now available</a>. For the most current information, including a complete
    list of impacted Red Hat products, please refer to the vulnerability\'s <a
    href="https://access.redhat.com/security/cve/CVE-2026-31431">CVE
    page</a>.</p>\n<h2>Mitigations</h2>\n<p>Any hardening measures that limit
    local access help reduce the risk of exploitation. Examples include
    disabling SSH, ensuring SELinux is in enforcing mode, using the default
    Security Context Constraints (SCC), running workloads as non-root, and
    restricting <code>oc debug</code> access to trusted cluster administrators.
    This list is not exhaustive, and the applicability of each measure should be
    evaluated in the context of your operational requirements and security
    policies. Additionally, disabling any single access method does not
    eliminate all other means by which a user could gain local
    access.</p>\n<h3>Overall Guidance</h3>\n<p>This advice is applicable to most
    Red Hat products.</p>\n<p>Warning: there may be performance impacts for
    modifying functionality that uses kernel cryptographic functions. While the
    affected module cannot be blocklisted due to being built into the kernel,
    the affected functions themselves can be blocked using the following boot
    arguments:</p>\n<pre><code>initcall_blacklist=algif_aead_init\n</code></pre><p>Alternatively,
    the af_alg interface itself can be
    blocked:</p>\n<pre><code>initcall_blacklist=af_alg_init\n</code></pre><p>As
    a further alternative, the affected algorithm can be
    blocked:</p>\n<pre><code>initcall_blacklist=crypto_authenc_esn_module_init\n</code></pre><h3>Product
